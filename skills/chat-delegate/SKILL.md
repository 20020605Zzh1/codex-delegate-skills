# Chat 对话与附件协作

把用户指定的材料和任务交给指定 Chat，保存完整返回并复核。长上下文放入真实 Markdown 附件，聊天正文保留任务、范围和输出要求。此技能面向普通 ChatGPT Chat，不把它当成 Codex 子任务或 API 调用。用户只要求查看时，仅定位、读取和核对，不切换设置或发送新消息。

## 参数

参数可从用户自然语言、现有会话和项目记录解析，无须要求用户填写表单。优先级为本轮明确要求、同一任务已确认参数、下列默认值；续接时保留此前明确选择，避免每轮重置。

| 参数 | 默认值 | 用途 |
|---|---|---|
| `chat_target` | 已明确指定的现有 Chat | 完整链接、ID、准确标题；`new` 仅用于用户明确要求新建时。重名且无法消歧时询问。 |
| `task` | 无 | 实际工作要求和期望输出。仅创建技能或准备附件不等于授权发送新任务。 |
| `sources` | 用户指定的文件或内容 | 只打包本次任务需要的材料。 |
| `thinking_level` | **`high`（高）** | 每次发送前设置并核实；用户明确覆盖优先。也可给出当前界面的准确档位名称。`keep` 表示明确保留当前档位。 |
| `model` | `keep` | 保留当前实际模型；只有用户指定时切换。模型与思考等级分别记录。 |
| `output_dir` | 当前项目的 `chat_tasks/<任务名>/` | 保存附件、短指令、会话链接、设置证据、原始回复及核对结果；已有任务记录目录优先复用。 |
| `revision_limit` | 当前任务约定 | 不凭空安排多轮优化；明确要求反馈循环时遵守该任务的回合上限与完成条件。 |

`thinking_level` 是本技能的执行参数，不是发给普通 Chat 的 API 字段。`send_message_to_thread` 的 `thinking/model` 覆盖只作用于 Codex 线程，不能用于证明普通 Chat 已切换。`high` 应落实到当前 UI 的“高”或经当前官方资料确认的对应档位；不得把 Pro、极高或耗时较长自动当成“高”。界面不支持或无法确认时，记录未落实的设置，先解决这个具体问题再发送依赖该设置的任务。

## 执行流程

1. **定位与续接。** 优先利用 `list_threads/read_thread` 获取指定 Chat 的准确标题、ID及所需上下文；工具不支持时读取已授权的网页。复用已有目标和授权，避免重复询问。没有明确目的地时先准备材料，再问一个必要的目标选择问题。创建普通 Chat 要选择 Chat 页面或当前工具明确支持的 Chat 类型，不默认新建 Codex/Work 任务。
2. **整理附件和短指令。** 阅读材料及项目约束。完整转交范围内保留原文，来源、版本与适用范围放在附件内；不为省上下文擅自截断或概括。长任务要求也可以入附件，短正文指向相关章节并说明本轮输出。原始 PDF/Word 先按相应工具提取并核对；不把二进制直接改扩展名。用下方脚本可靠打包 UTF-8 文本，也可直接上传已经合适的 Markdown。
3. **核实模型和思考等级。** 在实际目标 Chat 打开设置，记录模型和当前强度，落实用户指定值或默认 `high`。以选中项、当前档位文字或勾选状态为准；Chat 自报、提示词中的“请深入思考”和本地 manifest 不构成设置证据。具体 UI 方法见 [浏览器操作](references/browser-workflow.md)。
4. **上传并发送。** 用当前受支持的浏览器工具上传真实文件；看到文件卡片、上传完成且无错误后填入短指令。检查目标、附件、正文和等级，再发送一次。任务中已有明确的材料和目的地授权就直接完成，不额外设置一轮常规批准。对权限扩展等操作遵守当前工具要求。
5. **等待并读取。** “已发送”“正在思考”不算完成。等待生成结束，读取本轮完整可见回复，长回复必要时分段读取。若返回文件则按实际下载控件获取并打开核对。记录真实 Chat 链接与原始回复；截断、不支持、上传失败、未完成应如实保留。操作超时先核对页面是否已经完成，防止重复发送。
6. **复核和反馈。** 按具体任务检查范围、关键事实、引用、数字及成稿质量。需要返修且已获授权时在同一 Chat 给出明确、有限的反馈；长反馈仍用附件。达到任务约定即停止。原始 Chat 回复与 Codex 的整理稿分别保存，避免把本地改写冒称 Chat 原稿。
7. **交付。** 给出用户实际需要的结果、可打开的 Chat 链接和本地产物，必要时说明仍未验证的内容。用户要正文时不要用操作日志替代正文。变更网页后的截图及保留页面按当前浏览器工具要求处理。

## 可复用的打包工具

`scripts/prepare_packet.py` 只在本地生成附件、短指令和记录，不操作浏览器、不发送消息。使用已确认可用的 Python 3，示例中的路径替换为当前任务实际路径：

```powershell
python '<skill-dir>/scripts/prepare_packet.py' --source '<project>/材料.md' --source '<project>/参考.txt' --instruction-file '<project>/本轮指令.txt' --chat-target '<Chat链接或new>' --output-dir '<project>/chat_tasks/<任务名>/round-01'
```

- 不传 `--thinking-level` 时为 `high`；显式覆盖例如 `--thinking-level '极高'`，中文“高”会规范化为 `high`。
- 生成 `attachment.md`、`message.txt`、`manifest.json`；源文件正文逐字保留，UTF-8 BOM 仅作为编码标记移除，不改原文件。
- 附件仅标明文件名、来源编号及哈希，绝对本地路径只保存在本地 manifest。检查正文自身是否含不应转交的内容仍由当前任务决定。
- 目标目录已含同名产物则停止，另用下一轮目录，不覆盖之前的附件和回复。
- 默认状态为 `PREPARED_NOT_SENT`；`thinking_level_observed` 等实际字段留空。完成 UI 核对后再填入准确观察，不能把脚本默认值冒充成功证据。
- 每轮在相同目录另存 `response_raw.md` 和简短的核对记录，记录 requested/observed model、thinking、Chat URL、发送/完成状态和实际缺口。

## 长附件传递测试

只在用户要求测试读取能力时，在原文副本的开头、中段、结尾加入随机校验值，保存本地预期值。短正文只列提取任务，不包含答案；让 Chat 提取标记和几个已知原文位置，与本地逐字核对。通过表示该次上传、发送与抽样读取成功，不表述为全文理解或任意长度都可靠。一般写作任务不必插入测试标记。

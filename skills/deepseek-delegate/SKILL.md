# DeepSeek 任务派发与协作

Codex 负责拆解、派发、检查、反馈和项目维护；DeepSeek 通过用户已有的 Harness 执行明确交给它的任务。一次触发仅授权本次明确任务，不把其他工作自动派下去。

## 当前对话与项目

- 从当前 Codex 对话的项目上下文确定准确的项目目录，读取适用的 `AGENTS.md`。使用这个项目，不使用 Skill 所在目录、历史测试目录、其他对话的项目或擅自上溯的 Git 根目录。
- 以当前 Codex 对话 ID 作为 `conversation-key`；客户端未提供 ID 时，生成并在本次对话任务记录中保留一个本地关联键，标注 `codex_conversation_id=null`，不要冒充真实对话 ID。不要重新向用户询问已能从上下文确定的项目。
- 所有业务输入副本、Harness 原始会话、请求、结果、产物和维护记录均进入 `PROJECT_ROOT/deepseek_tasks/CONVERSATION_KEY/TASK_ID/` 或其所在对话的专用目录。输入副本位于 `workspace/inputs/`，模型产物位于 `workspace/artifacts/`。只有 Skill 的代码和共用运行依赖在用户级目录。
- 调用 `scripts/prepare_task.py`，显式传入当前项目和对话关联键。它会拒绝跨项目输入、路径逃逸、目录别名逃逸和同一任务的项目/会话/模型漂移。外部输入若是用户明确指定的，先在授权范围内复制到当前项目再准备任务。

## 派发与同一会话续聊

**默认推理等级为 Max (`reasoning_effort=max`)**。在任务准备、运行配置和实际 Harness 请求中使用并记录 Max；相关反馈保持同一等级。只有用户明确指定其他等级时才覆盖。历史 Low 记录保留原等级，不能重新标注成 Max。

首次使用先读 [安装与环境准备](references/setup.md)，再读 [运行入口](references/runtime.md)，使用已有官方 Harness Desktop CLI；不把普通 DeepSeek API 调用冒充 Harness，不换成另一个 Agent 产品。先确认入口、Python、SDK 和认证可用。

派发提示包含任务目标、指定输入、产物要求、允许修改的范围、验收条件和应回报的不确定事项。只发送完成任务所需的材料，默认通过输入副本工作；修改原项目文件必须在本次派发中明确列出已获授权的路径。

优先以 `Start-Delegate.ps1 -Serve` 启动一次。在其返回 `READY` 后，追加 JSON 行 `{"op":"turn","prompt":"..."}`；得到实际结果并检查后，在同一个运行入口追加修改反馈。保留运行入口 ID、任务目录、`session_id` 和进度到任务记录，跨上下文时先恢复这些记录。

保持相关反馈的 Harness 实例、会话、模型、系统提示和工具配置稳定。仅独立的新任务建立新任务目录。不要为了每一轮反馈重启进程或重写已有历史。当前 SDK 路径的跨进程同名会话恢复未被接受；进程丢失时保留记录并明确说明，不能删除日志强行复用 ID。缓存效果只报告实际 `cacheReadTokens`，不保证未来命中率。

不相关任务不要加入正在进行的会话。若任务需要额外的网络、依赖安装、后台进程或其他工具，按本次用户授权调整必要配置并保持对后续相关轮次稳定，不把连接测试的限制扩展成所有任务的永久禁令。

## 接收、复核与维护

运行入口每轮保存派发内容、模型完整答复、工具事件、实际用量和带 SHA256 的产物清单，初始状态为 `PENDING_CODEX_REVIEW`。模型返回 `completed`、清单生成成功和产物验收通过是三个独立状态。

Codex 按任务验收条件检查真实文件和必要运行结果；有问题就把具体反馈追加给同一会话。验收依据写入任务目录的 `REVIEW.md`，记录采用/拒绝的文件、当前 SHA256、验证结果及未完成项。复核后由 Codex 同步更新 `task.json` 与当前产物清单的相应验收状态，逐轮原始清单保留当时状态。采用的产物整理到本任务对应子项目的位置，维护必要的说明、引用关系、运行方式和项目状态；保留原始材料及有复核价值的候选和失败证据。

## 在 Harness 中看到对话

用户要求在原有 DeepSeek Harness 内看到实际派发、反馈和答复。任务关闭后按 [桌面对话同步](references/runtime.md#桌面对话同步) 调用 `scripts/sync_session.py`，用正常认证的本机 Desktop 控制接口登记到与本任务准确对应的工作区。原始会话继续保存在当前项目。

独立 SDK 日志与桌面版压缩格式可能不同。使用随 Skill 提供的官方存储转换器并校验全部事件；不要把未压缩文件直接塞进压缩记录库，不覆盖用户已续聊的副本，不直接改写正在使用的工作区索引。无需为了同步停止或重启一个正在干活的 Desktop。

API 登记成功记为 `DESKTOP_REGISTERED_API_READBACK_PASS`；再实际打开 Harness 会话核对可见内容，才记为 `NATIVE_UI_VERIFIED`。若认证或原生界面能力不可用，保存项目内的完整对话并明确 `DESKTOP_SYNC_PENDING` 或 `NATIVE_UI_CHECK_PENDING`，继续能独立完成的产物维护。当前提供的是关闭后的同步，不声称执行期间自动实时同步。

## 交付

简要说明 DeepSeek 实际完成了什么、Codex 如何复核和维护、产物所在当前项目的路径、Harness 会话名称、已验证状态及剩余事项。给出可点击的真实文件链接，用户无需学习调用命令。凭据、会话 cookie 和本地启动令牌只用于连接，不进入派发、答复、产物清单或交付文本。
